# LooMed — Technical Specification

**Version 0.1 · Last updated February 2026**

## Overview

LooMed is a protocol for patient-controlled medical records. The goal is simple: give patients portable, interoperable access to their medical data without requiring hospitals to cooperate first.

## Design Principles

1. **Patient sovereignty** — Records belong to patients, not institutions
2. **Zero-trust architecture** — No central authority required
3. **Progressive decentralization** — Start practical, move toward distributed
4. **Interoperability by design** — Standard formats, open protocols

## Architecture

### Data Model

Medical records are structured as:

```
Record {
  id: UUID
  patient_id: UUID
  timestamp: ISO8601
  record_type: enum
  data: EncryptedBlob
  signature: Signature
  metadata: Metadata
}
```

### Storage Layer

Records can be stored:
- Patient-controlled cloud storage
- Self-hosted servers
- Distributed storage networks
- Hospital systems (as fallback)

### Access Control

Access is granted via cryptographic capabilities:
- Patient holds root key
- Temporary access via time-limited tokens
- Revocation through capability expiry
- Audit log of all access
